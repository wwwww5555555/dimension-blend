# P2-w 调试通道（定位"效果没生效"）

> 版本：v0.24.0（versionCode 25）
> 入口：底部抽屉 → **高级** → 「调试通道：xxx」按钮，点一次切一个通道并立刻重渲染。

## 0. 先看这一行：实际用的是哪条管线

调试面板（画布左下角）会多出一行：

```
管线：图层管线
管线：旧 3-pass（降级）
```

**如果显示"旧 3-pass（降级）"，那么所有新效果（含冷暖双色、高度衰减）都没有参与渲染** ——
这不是参数问题，而是 shader 编译失败或 EGL 失败，代码里静默 fallback 了。
对应 logcat 会有 `图层管线失败，降级 CPU：<原因>`（现在带完整堆栈）。

这条诊断之所以必要：降级链保证了不崩溃，但也把"编译失败"变成了"画面看着没变化"，
非常容易被误判成"参数没生效"。

## 1. 通道总表

| 值 | 按钮显示 | 输出 | 判读 |
| --- | --- | --- | --- |
| 0 | 关闭 | 正常出图 | — |
| 1 | 法线 | `N*0.5+0.5` | 平涂区应为**中性灰**(0.5,0.5,0.5)；轮廓环带上有方向色。整屏蓝紫 = 梯度恒为 0 |
| 2 | 主光/环境权重 | `(keyWeight, ambientWeight, 0)` | 迎光面偏红、背光面偏绿。整屏单色 = `N·L` 没变化 |
| 3 | 双色光 | 左半 `uKeyLightColor` / 右半 `uAmbientColor` | 左右必须明显不同；都是白/灰 = 取色不对 |
| 4 | 高度掩码 | `vec3(heightWeight)` | 顶部接近白、底部接近黑。全黑 = uv.y 或 uniform 有问题 |
| 5 | 包裹强度 | `vec3(luma(spill)*2)` | 只在轮廓带非零；全黑 = 强度为 0 或 wrapMask 为 0 |
| 6 | 阴影遮挡 | `vec3(occlusion)` | 投影覆盖处 < 1 |
| 7 | 包裹蒙版 | `vec3(wrapMask)` | 只在轮廓 1~3px 环带非零 |

**为什么这些通道"值就是颜色"**：正常路径里 P2-w 会被合成 Screen、被 DOF/调色/暗角处理、
最后还要 Reinhard + sRGB 编码 —— 任何一步都会改变数值。调试路径做了三处直通：

1. `FRAG_P2_W`：debug 分支直接输出中间量；
2. `FRAG_COMPOSITE`：`uDebug > 0` 时直接输出 P2-w 纹理，**绕过 P1/P2 混合**；
3. `FRAG_FXAA`：`uDebug > 0` 时**跳过 tonemap 与 gamma**；
4. Kotlin 侧：debug 模式下 DOF / 调色 / Looks / 暗角四个 pass 整段跳过。

所以屏幕灰度 = 变量值，不会因为色调映射而偏移。

## 2. 关于"法线"的真相

**代码里没有 `getNormal()` 函数** —— 之前也从没有过。P2-w 的法线是**从 alpha 场求梯度**：

```glsl
vec2 grad = vec2(a(uv+dx) - a(uv-dx), a(uv+dy) - a(uv-dy));
vec2 nOut = -normalize(grad + vec2(1e-5));
```

### 这里有一个真 bug，已修

`normalize(grad + vec2(1e-5))` 在 `grad == 0`（平涂区）时不会得到零向量，而是得到
**固定的 (0.707, 0.707)**，取负后是 (-0.707, -0.707) —— 一个永远朝左上的 45° 法线。
后果：平涂区的 `N·L` 恒为常数，`keyWeight`/`ambientWeight` 整片不变，
**暖冷两色在画面内部完全拉不开**，只有在极窄的轮廓环带上才有变化。

现在改为：

```glsl
float gl = length(grad);
vec2 nOut = gl > 1e-4 ? -grad / gl : vec2(0.0);
```

梯度为 0 时给零向量 → `N·L = 0` → `keyWeight = 0`、`ambientWeight ≈ 0.8`（偏环境色）。
这也是物理上正确的：2D 抠图没有深度，平涂区没有法线，不该凭空给一个方向。

> 通道 1 里，平涂区显示 (0.5, 0.5, 0.5) 灰色是**正确的**，不是"没算出来"；
> 只有轮廓环带上出现方向色才说明梯度在工作。整屏只有一个颜色（无环带）= 真有问题。

## 3. 双色到底怎么取的（是否被设成白色）

`core-pipeline/SceneLightColors.kt`：

```kotlin
val cutKey = cutFromTop(hist, max(1, round(n * 0.05)))    // 从 255 往下累计到 5%
val cutAmb = cutFromBottom(hist, max(1, round(n * 0.50))) // 从 0 往上累计到 50%
// 主光：luma >= cutKey 的均值；环境：luma < cutAmb（严格小于）的均值
```

- **不是 `(1,1,1)`**：只有背景真的过曝成全白时主光才会是白，这本身就是有效结果
  （说明这张背景没有可用主光色）。
- 默认兜底：`KEY_NEUTRAL = 0xFFFFE3C0`、`AMBIENT_NEUTRAL = 0xFF9AA6B4`（只有空输入才用）。
- 通道 3 是判断它最直接的方式：**左半 = 主光、右半 = 环境**，两半颜色差异小于肉眼阈值时，
  冷暖分离本身就不会有可见效果（低饱和背景的常见情况）。

## 4. 高度为什么"看起来没衰减"

本工程 `uv.y = 1` 是**画面底部**（与 P2 脚底渐变同一约定），所以：

```glsl
heightWeight = 1.0 - smoothstep(uHeightStart, uHeightEnd, uv.y);   // 0.70 / 1.0
```

- 顶部（y 小）→ 1；底部（y→1）→ 0。
- 通道 4 应该看到**上白下黑**。如果全黑：`uHeightStart/End` 没传到（GLSL 里默认 0，
  `smoothstep(0,0,x)` 是未定义行为，某些驱动直接返回 0 或 1）。
- 已核对：`uHeightStart` / `uHeightEnd` 三个环节（Params → 管线默认值 → `uni1f`）都在。

## 5. 如果通道都有值、但正片看不出来

那说明**强度不够，而不是断了**。按当前默认值估算：

```
spill ≈ tinted(0.23) × wrapMask(0.9) × height(≤1) × occlusion(≤1) × 0.25 × 2.0 ≈ 0.10 (线性)
```

Screen 叠到 0.5 的底上 → 0.55，转 sRGB 约 +7/255，且只作用在 2~3px 的环带上。
在这个量级上，"看起来没变化"是正常的。**把「光包裹强度」滑杆从 0.25 提到 0.5~0.6** 就能看出来。

建议的验证顺序：

1. 看「管线」一行 → 排除降级；
2. 通道 5（强度）→ 轮廓上有没有值；
3. 有值但弱 → 提高光包裹强度滑杆；
4. 通道 5 全黑 → 依次看 7（蒙版）、4（高度）、6（遮挡），找到归零的那一环；
5. 通道 3 左右几乎同色 → 背景本身没有冷暖差，换一张逆光/夕阳素材验证。
